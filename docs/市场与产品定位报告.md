# Pawly 宝狸 · 市场与产品定位报告

**版本** 2026.09　|　**状态** 定位重大调整后的第一版　|　**替代** 2026.08 的 C 端联盟佣金方案

---

## 摘要

Pawly 从「面向宠主的 AI 导购助手」转为**面向宠物终端商家的 AI 能力供应商**。

主平台继续对公众免费开放，不参与商品交易；收入来自宠物店、宠物医院等终端商家，
按其售出的宠物数量分成。商家版是主平台同一套能力按签约品类收窄后的配置态，逐家部署。
部署与使用中产生的问答语料、商品结构、个体档案与养护结果回流核心知识库，
使主平台的科普与 AI 回答持续变准。

首轮切入异宠品类完成模式验证，内核与配置层再复制到犬猫。

**一句话**：通用内核对外，逐家部署至商家现场，经验回流内核——
结构上对应 Palantir 的 Forward Deployed Engineer 模式。

## 一、为什么换定位

### 1.1 原方案的三个结构性问题

2026.08 版的模式是：宠主在 Pawly 咨询 → 跳转第三方电商下单 → Pawly 按订单收 5% 联盟佣金。
这个模式有三处硬伤，且都不是执行问题，是结构问题。

| 问题 | 为什么解不掉 |
|---|---|
| **归因不在自己手里** | 成交发生在别人的平台，订单回传、归因规则、佣金率全部由平台单方面决定。比价、跨平台下单、规则变更都会直接侵蚀收入，而我们没有任何议价筹码。 |
| **公信力与收入互相打架** | 靠佣金挣钱，就有推高客单价的动机；而用户来 Pawly 的唯一理由是「这里的建议是中立的」。收入越依赖佣金，中立性越可疑。 |
| **获客成本与留存赛跑** | C 端逐个获客，每个用户的 LTV 是若干笔佣金的期望值。在留存未验证前放大投放，是拿现金换未被证实的假设。 |

### 1.2 新方案如何绕开

- **付费方换成商家**：收入绑在商家的售宠成交上，不依赖第三方平台的归因回传。
- **交易与建议分离**：主平台明确不参与商品交易与分佣，交易环节统一设置在标识明确的商家版内。
  中立性因此可以被结构性地证明，而不是靠承诺。
- **获客从「逐个用户」变成「逐家商家」**：一家商家带来它全部的售宠顾客，
  获客单位从个人变成渠道，单位获客成本大幅下降。

### 1.3 转型代价（需要正视）

- 已有的 C 端资产（300+ 问卷、100+ 体验用户、50+ 反馈）不能直接换算成 B 端验证，
  付费意愿必须重新验证。
- 销售动作从线上投放变成地推，对团队能力的要求完全不同。
- 收入确认从「用户下单即结算」变成「商家签约 + 按激活结算」，回款周期变长。

## 二、市场

### 2.1 切入产业链的哪一层

产业链自上而下是：品牌与供应商 → 经销与批发 → 终端商家（宠物店 / 卖家 / 医院）→ 宠主。

**Pawly 切终端商家这一层**，理由有二：

1. **宠主的购买决策高度依赖商家建议**——终端商家是决策发生的地方，不是流量最大的地方，
   但是转化率最高的地方。
2. **这一层的专业能力供给是缺的**：终端商家数量众多、单体规模小、数字化程度低，
   缺少可复用的专业内容与问答能力；而品牌方预算主要投向渠道与营销，
   终端服务能力的投入占比很低。

也就是说，这一层有明确需求、有支付能力，但没有人给它供给。

### 2.2 市场规模

口径限定为 **AI 养护知识与导购能力层的 B 端年度可支出**，不是整个宠物消费市场。

| 层级 | 规模 | 说明 |
|---|---|---|
| TAM | 22 亿元 / 年 | 终端商家在这一能力层的可支出总量 |
| SAM | 6.0 亿元 / 年 | 可服务总市场 |
| SOM | 500—1,000 万元 | 第三年可达营收 |

背景数据：2025 年城镇犬猫消费 3,126 亿元（派读《2026 年中国宠物行业白皮书》）。
这个数字只用来说明行业体量，**不作为我们的分母**——口径要主动说明，不等追问。

### 2.3 为什么先做异宠

现有 AI 产品集中在犬猫的医疗诊断方向（宠智灵、灵兽等），
其壁垒是临床病例、影像与自研硬件；通用大模型与内容代运营则答案缺少依据来源、代运营成本高。
**日常养护 × 异宠**这个格子，目前尚无成规模的参与者。

选异宠的三条依据：

1. **新手期问题密集**——温湿度、垫材、饲料与发育判断集中在购入后的前三十天，
   这正好是商家交付后最需要支撑的窗口。
2. **商家承担售后压力**——饲养失败容易转化为退换与差评，而商家缺少应对手段。
   这是**商家自己的痛**，不是宠主的痛，付费动机因此成立。
3. **用户价值密度高**——忠实用户的单体价值高于泛用户，细分品类具备做深空间。

**天花板问题的回答**：异宠是验证场，不是终局。内核与配置层在异宠跑通后可直接复制到犬猫，
届时面对的是已被验证的模式，而不是从零开始。

## 三、产品定位

### 3.1 两个面，一套能力

| | Pawly 主平台 | 商家版 |
|---|---|---|
| 面向 | 大众，持续免费开放 | 按签约商家配置生成 |
| AI 问答 | 覆盖犬猫与 6 类异宠 | 收窄至签约品类 |
| 科普 | 循证撰写，标注依据来源 | 同一知识库的品类分册 |
| 个体档案 | 品种、月龄与饲养环境 | 与主平台同一模块 |
| 选购 | 挑选标准与成分对比，**无交易环节** | 接入商家 SKU |
| 社区 | 保留开放 | 工单转至商家联系方式 |

**主平台的 C 端服务一项都没有减少。** 商家版不是另一个产品，
是同一套能力按签约品类收窄、并接入商家商品后的结果。

主平台在商业上承担两个职能：为内核提供内容来源，为商家版提供公信力支撑。

### 3.2 FDE 模式：为什么这不是外包

这是最容易被误读、也最需要讲清的一点。

| | 外包 / 定制开发 | Pawly |
|---|---|---|
| 交付物 | 每家一套独立代码 | 同一份代码的不同**配置态** |
| 部署动作 | 开发 | 填配置项（标识、品类范围、商品库、工单转接） |
| 上线周期 | 按项目计 | 半天 |
| 边际成本 | 恒定或上升 | 随家数下降 |
| 经验沉淀 | 留在项目里 | 回流内核，后续商家直接受益 |

**证据是部署人时曲线**：第 1 家 40 人时 → 第 3 家 20 → 第 5 家 10 → 第 10 家 5 → 稳态 4。
下降来自三处：品类知识库复用（同品类后续商家无需重建内容）、
配置项标准化（首家验证过的参数固化为默认值）、交付流程模板化（签约、导入、培训形成固定动作）。

**规模化临界点**：单品类累计部署约 10 家后，新增商家不再需要开发介入。

> 这条曲线目前是内部测算，必须用首批试点校准。它是整个模式最关键的一个待验证数字——
> 曲线不下降，模式就是外包。

### 3.3 技术结构

四层，差异只发生在最上面一层：

| 层 | 内容 | 范围 |
|---|---|---|
| 商家配置层 | 标识、界面、开放品类、商品库、工单转接 | **每家独有** |
| 品类知识库 | 兔 / 爬宠 / 鹦鹉 / 水族…按品类分册，循证标注 | 按签约品类开放 |
| 检索与生成层 | 检索增强生成，答案携带依据来源与免责声明 | 所有商家共用 |
| 底座模型 | 已完成算法备案的大模型服务 | 所有商家共用 |

**为什么用检索增强而不是微调**：异宠语料规模有限且更新频繁，知识维护以文档更新为主。
更重要的是——**壁垒来自知识库而非模型权重，微调的投入不形成壁垒**。
结构上的收益是：新增商家只调配置层，无需开发介入；知识更新改文档即可，不必重训模型。

上线前置条件：企业主体 + 深度合成类目备案。

## 四、运营闭环

```
核心平台 ──按商家配置部署──▶ 商家版 ──随宠物交付──▶ 宠主使用
   ▲                                                      │
   └──────────── 回流至内核 ◀──── 沉淀使用数据 ◀───────────┘
```

交付动线：商家签约（分成或年费）→ 配置部署（半天上线）→ 随宠物交付（二维码）
→ 扫码建档（三十秒出计划）→ 日常使用（问答与选购）→ 工单转接（转由商家处理）。

### 4.1 知识回流：由点及面

| 层级 | 范围 | 沉淀成什么 |
|---|---|---|
| **点** | 单家商家与其顾客 | 真实问答、饲养环境参数、商品选择与售后记录，构成原始素材 |
| **线** | 同品类多家商家 | 同一条建议在多个个体上获得结果反馈，沉淀为该品类的知识分册与话术模板 |
| **面** | 跨品类与跨区域 | 品类之间共用同一套结构，个体档案在商家之间迁移，形成知识网络 |

回流的四类内容与各自的作用：

- **问答语料** → 暴露知识库的覆盖缺口，补齐后提升应答范围
- **商品与库存结构** → 形成各品类的选品标准与商品匹配规则
- **个体档案与养护结果** → 使建议获得可追溯的效果反馈，提升置信度
- **部署配置与话术模板** → 沉淀为后续商家的默认配置，缩短上线周期

第三类是关键：它让一条建议从「文献上的说法」变成「在多个个体上验证过的结论」。
这是通用模型拿不到的数据，也是主平台科普与 AI 回答持续变准的来源。

**核心知识库的价值不随单家商家的变动而减少**——这一条决定了客户流失不等于资产流失。

## 五、收入模型

**付费动机来自售宠成交与耗材复购。节省人力属于成本项，付费意愿低于收入项。**
这是定价逻辑的起点：卖「帮你多卖出去」比卖「帮你省人」好卖。

| 来源 | 定价 | 启动时点 |
|---|---|---|
| **售宠套餐分成（主模型）** | 20—30 元 / 激活用户；商家售出一只宠物即包含一年养护顾问服务 | 首轮即启动 |
| 商家版内用品分佣 | 主粮零食 3%—8%，用品 5%—12% | 售宠分成跑通后 |
| 年费订阅 | 2,000—5,000 元 / 年（测算） | 规模形成后转年费或混合 |
| 品牌方内容包与洞察报告 | 单篇 300—1,500 元 | 第 7—12 个月 |

以中等规模异宠商家测算：年售 200—500 只 → 对应 4,000—15,000 元 / 年。待首家试点校准。

**推进顺序**：售宠分成打底 → 商家版内分佣 → 规模形成后转年费或混合 → 语料积累后提供洞察报告。

**主平台不参与商品交易与分佣。** 公众平台同时提供中立建议与商品销售会影响公信力，
交易环节统一设置在标识明确的商家版内。

收入规模与商家销售规模同步增长，**续费决策依据由支出转为收益**——
商家判断的不是「这笔钱值不值得花」，而是「这套东西帮我多卖了多少」。

## 六、壁垒

三项资产，**均独立于上游模型的版本更新**：

| | 是什么 | 为什么难复制 |
|---|---|---|
| **入口** | 商家私域场景中随宠物交付的扫码入口 | 通用产品难以进入单个商家的售后流程 |
| **数据** | 品类知识库、商品匹配规则与养护结果记录 | 通用模型不掌握单店商品与个体养护轨迹 |
| **关系** | 宠物个体档案与连续的养护跟踪记录 | 单次对话难以形成连续的养护记录 |

复制这三项需要逐家进入商家的售后场景，并积累同等时长的养护记录——
这是时间成本，不是资金成本，因此不能靠融资追平。

**合规边界**：仅提供养护知识与选购参考，不替代兽医诊断；
内容由兽医与训犬师撰写，异宠医生署名审校。

**数据授权**：商家合同中约定脱敏与聚合使用范围，回流数据仅用于改进知识库。

## 七、验证计划与财务

### 7.1 八周验证

本轮验证两项指标：**付费意愿**与**部署效率**。

| 周次 | 动作 |
|---|---|
| 第 1—2 周 | 门店调研 15—20 家（异宠商家不少于 8 家）· 首批品类知识库撰写 |
| 第 3—4 周 | 配置层与商家版模板 · 深度合成类目申请 · 异宠医生审校对接 |
| 第 5—6 周 | **首家商家上线并收费**（500—1,000 元）· 获得真实激活数据 · 形成完整交付流程 |
| 第 7—8 周 | 复盘定价结构 · 洽谈第二、三家商家 · 形成可对外引用的案例 |

**首笔收入的时点为第六周。** 此后按月新增商家，观测部署人时随家数的变化。

付费意愿必须通过**收费试点**获得验证——口头意向不算证据，这是本轮的第一优先级。

### 7.2 三年财务

| | 第 1 年 | 第 2 年 | 第 3 年 |
|---|---|---|---|
| 签约商家 | 20 家 | 100 家 | 500 家 |
| 营收 | 约 10 万元 | 约 100 万元 | 500—1,000 万元 |
| 损益 | 预计约亏损 15 万元 | 勉强达到收支平衡 | 税前利润约 75 万元 |

采用 SOM 保守口径。单商家年均贡献约 1 万元，三年保持同一量级，规模靠家数增长。

**资金用途**：市场与获客 40% · 产品研发 30% · 合规服务 10% · 云与 AI 10% · 运营储备 10%。

**成本结构**：

- 模型调用——随激活用户数线性增长，构成分成定价的下限依据
- 内容生产——单品类知识库属于一次性投入，可在商家之间复用
- 地推与部署——本阶段的主要人力投入，同时是部署人时曲线的验证对象

项目为轻资产结构，服务器资源由合作教师提供，本阶段现金支出集中于内容生产与地推。

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| **上游模型覆盖本项功能** | 壁垒在入口、数据与关系三项资产，不在模型能力；三项均独立于模型版本更新 |
| **内容可信度** | 循证撰写、标注依据来源、异宠医生署名审校；不替代兽医诊断的边界写进产品逻辑 |
| **小程序上线资质** | 企业主体已具备（2026.07.21 注册，注册资本 200 万元）；深度合成类目在第 3—4 周申请 |
| **部署人时不下降** | 这是模式成立与否的判据。若首批 3—5 家未见下降，说明配置层抽象不足，需回头改产品而非继续扩张 |
| **商家续费率低** | 续费依据是收益而非支出，需在第 7—8 周复盘中确认商家能否感知到售宠转化的提升 |
| **异宠品类天花板** | 异宠是验证场；内核与配置层可复制到犬猫 |
