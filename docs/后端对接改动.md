# 后端要配合改的三处（Pawly 网页端仓库）

小程序端复用网页端**同一套 `/api/*` 接口**，页面代码不需要为小程序单独写后端。
但有三处必须在 `Celveen/Pawly` 仓库里改一下，改动都很小。

---

## 1. 身份透传：`lib/session.ts`（必改）

网页端用 httpOnly Cookie `pawly_uid` 标识用户。小程序的 `wx.request` **没有可靠的 Cookie 容器**
（iOS/Android/开发者工具行为不一致，httpOnly 也读不到），所以小程序改用请求头 `x-pawly-uid`
透传同一个 id。后端优先读这个头，读不到再回落到 Cookie，网页端行为完全不受影响。

```diff
--- a/lib/session.ts
+++ b/lib/session.ts
-import { cookies } from 'next/headers';
+import { cookies, headers } from 'next/headers';
 import { randomUUID } from 'crypto';

 const COOKIE = 'pawly_uid';

 export function getOrCreateUserId(): string {
+  // 小程序端没有可靠的 Cookie 容器，改用请求头透传同一个 id。
+  // 网页端不会带这个头，所以下面的 Cookie 逻辑原样保留。
+  try {
+    const fromHeader = headers().get('x-pawly-uid');
+    if (fromHeader && /^[\w-]{20,40}$/.test(fromHeader)) return fromHeader;
+  } catch {
+    // 静态渲染场景下 headers() 会抛，忽略即可
+  }
   const jar = cookies();
   const existing = jar.get(COOKIE)?.value;
   if (existing && /^[\w-]{20,40}$/.test(existing)) return existing;
   const id = randomUUID();
   jar.set(COOKIE, id, cookieOpts);
   return id;
 }
```

> 安全性说明：这和原来的匿名 Cookie 是同一个安全模型 —— 一个随机 UUID 就是身份。
> 如果之后要提高强度（比如签名 token），网页端和小程序端要一起改。

## 2. 登录/注册把 `userId` 回传（必改）

小程序拿到 `userId` 之后写进本地存储，后续请求都用它当 `x-pawly-uid`。
服务层（`server/services.ts`）本来就返回了 `userId`，只是 BFF 路由把它删掉了，加回去即可。

```diff
--- a/app/api/auth/login/route.ts
+++ b/app/api/auth/login/route.ts
   setUserCookie(r.data.userId);
-  return NextResponse.json({ ok: true, account: r.data.account, kind: r.data.kind });
+  return NextResponse.json({ ok: true, userId: r.data.userId, account: r.data.account, kind: r.data.kind });
```

```diff
--- a/app/api/auth/register/route.ts
+++ b/app/api/auth/register/route.ts
   setUserCookie(r.data.userId);
-  return NextResponse.json({ ok: true, account: r.data.account, kind: r.data.kind });
+  return NextResponse.json({ ok: true, userId: r.data.userId, account: r.data.account, kind: r.data.kind });
```

改完之后，小程序上的「登录 / 注册」就能把游客期间产生的数据合并进账号
（合并逻辑在 `server/auth.ts` 里，本来就有）。

## 3. 微信一键登录（可选，想上线基本要做）

现在小程序登录页的「微信一键登录」按钮只弹一个说明。要真跑通，需要后端加一个路由：

**新增 `app/api/auth/wechat/route.ts`：**

```ts
// 微信小程序登录：用 wx.login 拿到的 code 换 openid，再落到 Pawly 的用户体系
import { NextRequest, NextResponse } from 'next/server';
import { rpc } from '@/lib/gateway';
import { getOrCreateUserId, setUserCookie } from '@/lib/session';

export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

export async function POST(req: NextRequest) {
  const { code } = await req.json().catch(() => ({}));
  if (!code) return NextResponse.json({ error: '缺少 code' }, { status: 400 });

  const url = `https://api.weixin.qq.com/sns/jscode2session`
    + `?appid=${process.env.WX_APPID}`
    + `&secret=${process.env.WX_SECRET}`
    + `&js_code=${code}&grant_type=authorization_code`;

  const res = await fetch(url, { cache: 'no-store' }).then((r) => r.json());
  if (!res.openid) return NextResponse.json({ error: res.errmsg || '微信登录失败' }, { status: 400 });

  // 建议在 services.ts 里加一个 'auth.loginWechat'，行为参照 auth.loginPassword：
  // 按 openid 找用户，没有就建一个，并把当前游客 id 的数据合并过去。
  const r = await rpc<{ userId: string }>('auth.loginWechat', getOrCreateUserId(), { openid: res.openid, unionid: res.unionid });
  if (!r.ok) return NextResponse.json({ error: r.error }, { status: r.status });

  setUserCookie(r.data.userId);
  return NextResponse.json({ ok: true, userId: r.data.userId });
}
```

**数据库**：`User` 表加一列 `openid String? @unique`（`prisma/schema.prisma`），然后 `npx prisma db push`。

**环境变量**（`.env.local` / Vercel 环境变量）：

```
WX_APPID=你的小程序 AppID
WX_SECRET=你的小程序 AppSecret
```

⚠️ `WX_SECRET` 只能放服务端环境变量，**绝对不要**写进小程序代码或提交到仓库。

**小程序端接线**：把 `packageUser/pages/login/index.js` 里的 `wxLogin()` 换成

```js
wxLogin() {
  wx.login({
    success: ({ code }) => {
      require('../../../api/request').post('/api/auth/wechat', { code })
        .then((r) => { api.setUid(r.userId); return app.refreshMe(); })
        .then(() => { toast('登录成功'); setTimeout(() => wx.navigateBack(), 600); })
        .catch((e) => toast(e.message || '登录失败'));
    },
  });
}
```

## 顺带说明：DeepSeek 的 Key 在哪

**不用动，也不要动。** Key 一直只在后端：

- 位置：Pawly 仓库的 `.env.local`（本地）或 Vercel → Settings → Environment Variables（线上）
- 变量名：`DEEPSEEK_API_KEY`、`PAWLY_MODEL`、`DEEPSEEK_BASE_URL`
- 小程序只调 `/api/chat` 和 `/api/chat/stream`，Key 全程不出后端。

**小程序代码里不需要、也不应该出现任何 API Key。** 小程序包是可以被反编译的，
任何写进前端的密钥都等于公开。
