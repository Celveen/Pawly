## 一、这八周要交付什么

分工从交付倒推。PPT 第 12 页的验证计划里，**第 5—6 周首家商家上线并收费**是唯一的硬节点，
它要求下面五件事同时就绪：

| 必须就绪 | 为什么 |
|---|---|
| 小程序能上线（或 H5 兜底能用） | 顾客扫码的入口 |
| 商家配置层 | 「部署 = 填配置」，没有它首家就是定制开发 |
| 扫码建档 → 三十天养护计划 | 商家版的核心交付物 |
| 激活计量 | **按激活结算，这是收钱的依据** |
| 首批品类（兔）知识库可检索 | 商家版回答的内容来源 |

另有两件事第 8 周前要有雏形：知识回流管线（模式成立的关键）、部署人时记录（验证曲线用）。

## 二、四个角色

### 角色 A · 安全与合规　负责人：________

**一句话**：决定「能不能上线」和「数据能不能用」。

| 负责 | 说明 |
|---|---|
| 备案与资质的技术线 | ICP 备案、公安联网备案、小程序备案与类目（含深度合成相关类目）、大模型上线登记的技术材料（内容安全机制、安全评估说明）。代办机构跑流程，技术材料由 A 出 |
| 服务器迁移与运维 | 小程序的请求域名必须是已 ICP 备案的 HTTPS 域名，现有 Vercel / Neon 部署不满足。迁到合作教师提供的境内服务器：dev / staging / prod 三套环境、证书、备份与恢复演练 |
| 日志留存 | 网络日志留存不少于六个月，上线即开 |
| 应用安全 | API 限流、小程序会话与商家后台鉴权、DeepSeek 等密钥管理（不入库、不进前端）、审计日志、首家上线前一次渗透测试 |
| **多租户隔离** | 商家 A 看不到商家 B 的顾客、档案、工单。隔离的测试用例由 A 写、A 签字放行 |
| 个人信息保护 | 隐私政策与用户协议的技术落地：首次授权、撤回同意、数据导出与删除；敏感字段加密 |
| 回流数据脱敏 | 与 C 共同制定脱敏与聚合规则，**A 有否决权**；这也是商家合同数据条款的技术附件 |

**不负责**：功能开发。

**衡量**：首家上线前零高危漏洞；备案不成为关键路径的卡点；租户隔离用例全部通过。

---

### 角色 B · Agent　负责人：________

**一句话**：管在线对话链路——用户问一句，到回答流式吐完。

现有代码：`server/agent/`（除 `knowledge/retrieval/`）、`server/deepseek.ts`、`server/moderation.ts`、`server/tokenMeter.ts`。

| 负责 | 说明 |
|---|---|
| 商家版对话行为 | 按商家配置收窄品类；推荐只从该商家商品库出；工单转接的触发条件（售后、退换、健康高风险）；**非签约品类的问题怎么答**需要先定策略 |
| 养护计划的对话侧 | 扫码后的首轮对话、计划解读、日常跟进问答 |
| 模型成本 | **单个激活用户在一年服务期内的模型调用成本**。分成是 20—30 元 / 激活，这个数必须测出来并压到远低于它——它是定价下限 |
| 容灾与性能 | DeepSeek 单点依赖，至少接一个备用模型做切换；首字延迟与压测（已有 100 题压测，扩展到商家版场景） |
| 对话层护栏 | 不诊断边界、提示词注入防御、AI 生成内容的显式标识 |

**不负责**：检索怎么找到资料（C）、商家配置存在哪（D）。

**衡量**：单激活用户年模型成本；P95 首字延迟；安全测试集通过率。

---

### 角色 C · 算法　负责人：________

**一句话**：管「找得准」和「越用越准」——检索质量、知识库工程、回流管线、离线评测。

现有代码：`server/agent/knowledge/retrieval/`、`content/`、`scripts/import-knowledge.ts`、`scripts/validate-knowledge.ts`、`scripts/check-knowledge-coverage.ts`。

| 负责 | 说明 |
|---|---|
| 检索升级 | 现在是「物种 + 大类」关键词召回，升级为向量检索 + 重排。**按签约品类过滤放在检索层做**，不靠提示词约束 |
| 品类知识库工程 | 兔类分册的结构化（饲养环境参数、发育阶段、常见问题）；审校状态字段——**异宠医生审校通过的条目才能被检索到** |
| 养护计划生成 | 基于档案（品种、月龄、饲养环境）的规则 + 模板，保证可审校、可复现，不走纯生成 |
| 商品匹配 | 商家 SKU 结构各不相同，需要归一化后与知识库的选购标准匹配 |
| **知识回流管线** | 问答语料 → 聚类 → 覆盖缺口清单（检索未命中 / 低置信问题）→ 交内容侧补写；养护结果回收 → 建议置信度。这是「内核越用越准」的实际实现 |
| 离线评测 | 按品类建评测集；每次改检索或知识库都跑回归 |

**不负责**：知识内容本身的撰写（兽医 / 训犬师 / 异宠医生）。

**衡量**：兔类评测集检索召回；缺口清单每周产出；计划生成同输入同输出。

---

### 角色 D · 开发　负责人：________

**一句话**：管用户和商家能摸到的一切——小程序、商家后台、业务接口、数据模型。

现有代码：`app/`、`components/`、`prisma/`、`lib/`、`server/services.ts` 等业务层；新增小程序工程与商家后台。

| 负责 | 说明 |
|---|---|
| 小程序 | **范围收窄**：扫码建档、养护计划、问答、档案、工单转接。社区、商城、私信先不搬进小程序——商家版是品类切片，不是主平台的移植 |
| 小程序能力 | 微信登录与手机号验证、带参二维码（参数带商家 ID 与批次）、订阅消息（计划提醒） |
| 多租户数据模型 | 新增 `Merchant`、`MerchantConfig`（标识、开放品类、工单联系方式）、`MerchantProduct`、`Activation`、`Ticket`；现有 `User` / `Pet` 增加商家归属 |
| 商家配置后台 | 让「部署 = 填配置」成立。首家可以脚本加表单，**第三家之前必须表单化**——部署人时曲线直接依赖它 |
| **激活计量与对账** | 收钱的依据：防重复计数、防刷、商家可查明细、按月出账单。必须可审计 |
| 工程基建 | CI / CD（仓库目前没有 workflows）、数据库迁移 |

**衡量**：第 5—6 周首家上线；单家配置上线不超过半天；账单与商家核对零差异。

## 三、交接面

四个人的活在这几处咬合，接口先定、再各自开工。

| 交接物 | 从 → 到 | 第几周前定 |
|---|---|---|
| 商家配置的数据结构（开放品类、商品库、工单方式） | D → B、C | 第 2 周 |
| 检索接口：输入问题 + 品类过滤，输出带来源的片段 | C → B | 第 3 周 |
| 养护计划接口：输入档案，输出三十天计划 | C → B、D | 第 4 周 |
| 激活事件：扫码、建档完成的埋点 | D → A（审防刷）、B（算成本） | 第 3 周 |
| 回流语料导出格式与脱敏规则 | C ↔ A | 第 6 周 |
| 租户隔离测试用例 | A → D | 第 4 周 |

**Review 规则**：

- 涉及鉴权、个人信息、租户隔离的改动，必须 A review
- 涉及检索、知识库结构、评测集的改动，必须 C review
- 涉及 `server/agent/` 编排与提示词的改动，必须 B review

## 四、八周排期

| 周次 | A 安全合规 | B Agent | C 算法 | D 开发 |
|---|---|---|---|---|
| **1—2** | 启动 ICP / 小程序备案 / 大模型登记材料；服务器迁移方案 | 定商家版对话策略（非签约品类怎么答、何时转工单） | 兔类分册结构设计；评测集第一版 | 多租户数据模型；小程序工程搭建；配置结构交给 B、C |
| **3—4** | 境内环境上线；限流、鉴权、日志；租户隔离用例 | 接商家配置与检索接口；备用模型切换 | 向量检索上线；养护计划规则 + 模板 | 扫码建档、计划页、问答页；激活计量；商家配置后台 |
| **5—6** | 渗透测试；上线放行 | 首家压测；单激活成本实测 | 首家数据上的检索评测 | **首家上线并收费**；工单转接跑通 |
| **7—8** | 回流脱敏规则定稿 | 按首家真实对话调策略 | 回流管线雏形；第一份缺口清单 | 配置后台表单化；记录部署人时；准备第二、三家 |

## 五、需要先拍板的三件事

这三件不是技术问题，但不定下来技术没法开工。建议林晨第 1 周内定。

1. **「激活」的定义。** 扫码算，还是扫码加完成建档算？它写进商家合同，也决定 D 怎么计数、A 怎么防刷。定义不清，第一次对账就会扯皮。
2. **非签约品类的问题怎么处理。** 兔类商家的顾客问猫的问题：拒答、引导去主平台，还是照常回答？影响 B 的对话策略和 C 的检索过滤。
3. **小程序过审前的兜底。** 备案周期不由团队决定。若第 5 周小程序还没过审，首家是否先用 H5（扫码打开网页版）上线收费？建议定为「是」——这样收费验证不被审核周期卡住，过审后再迁移。

## 六、与旧分工的差别

| | 旧分工（C 端电商） | 新分工（to B） |
|---|---|---|
| 后端重点 | 支付、订单履约、供应链对接 | 多租户、商家配置、激活计量 |
| AI 重点 | 导购推荐、转化率 | 品类收窄、单激活成本、知识回流 |
| 合规重点 | 增值电信许可、食品资质 | 小程序备案与类目、多租户隔离、回流数据脱敏 |
| 新增 | — | 算法单独成岗：检索质量与回流管线是模式能否「越用越准」的关键，不再是 Agent 的附属工作 |
